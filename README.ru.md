# voicetype

**Говорить агенту в терминале вместо того, чтобы ему печатать.**

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
![Platform](https://img.shields.io/badge/platform-Linux%20%2F%20X11-lightgrey)
![No local models](https://img.shields.io/badge/local%20models-none-green)

*English version: [README.md](README.md)*

Зажал клавишу, сказал что хочешь, получил окно с текстом, поправил, нажал
Enter — текст оказался в том терминале, где стоял курсор. Сделано под диктовку
длинных инструкций CLI-агентам по-русски, вперемешку с английскими терминами.

---

## Зачем это

Я целыми днями работаю с AI-агентами в терминале. Узким местом никогда не была
скорость печати — дело в том, что сформировавшуюся мысль проще **сказать**, чем
набрать. Пока допечатываешь третье предложение контекста, четвёртое уже
расплылось.

Так что это не программа диктовки вместо клавиатуры. Это способ занести абзац
замысла в строку терминала, не теряя мысль по дороге, и всё равно поправить его
руками, прежде чем он куда-то уйдёт.

Три вещи, которые нужно было сделать правильно:

- **Не путаться под ногами.** Один фоновый процесс, поднимается одной командой
  и одной же останавливается. Сам при загрузке машины не запускается. Пока
  остановлен, клавиша-триггер работает как обычная клавиша.
- **Понимать, как разработчики реально говорят.** Русский с вкраплениями
  английского: «заребейзь фичу на мейн» должно давать `rebase` и `main`, а не
  транслитерацию кириллицей.
- **Никогда не вставлять вслепую.** Всё проходит через окно правки. Именно там
  вставляется ссылка, чинится путь, дописывается флаг — всё то, что голосом не
  надиктуешь.

Дальше Enter — текст в терминале, ещё Enter — агент его читает.

## Как это работает

```
                 ┌─ зажал клавишу ──── говорю ──── отпустил ─┐
курсор в         │                                           │
терминале ───────┤  ИЛИ                                      ├──► бип
                 │                                           │
                 └─ тапнул ─ говорю ─ тапнул ещё раз ────────┘
                                     │
                   pw-record 16 кГц mono ─→ ffmpeg ─→ Opus в памяти
                                     ▼
              OpenAI  gpt-transcribe                          ~1–2 с
              keywords=<мой глоссарий>  languages=["ru","en"]
                                     ▼
              DeepSeek  deepseek-chat                          ~1–2 с
              пунктуация, «ээ», самоповторы
              ↳ шага нет вовсе, если не добавлять ключ
                                     ▼
                  ┌─────────────────────────────────┐
                  │  окно правки, поверх всех       │  ← бип
                  │  серым — предыдущий фрагмент    │
                  │  ─────────────────────────────  │
                  │  правь свободно, вставляй       │
                  │  ссылки, Ctrl+Z, Ctrl+V —       │
                  │  это настоящий редактор         │
                  │  Enter = вставить · Esc = нет   │
                  └─────────────────────────────────┘
                                     ▼
              фокус возвращается в исходное окно → вставка
              (буфер обмена восстанавливается) → курсор в конце
                                     │
                  ┌──────────────────┘
                  ▼
        нажал клавишу снова → продолжение встаёт следом,
        предыдущее остаётся целым
```

Локальных моделей нет. Распознавание — это вызов API, поэтому весь проект
занимает ~20 МБ зависимостей и стартует мгновенно: грузить в память нечего.

## Перед тем как клонировать — честные ограничения

- **Только X11.** Перехват клавиш работает через расширение RECORD, вставка —
  через XTEST. В Wayland и то и другое намеренно недоступно обычным
  приложениям. Проверить: `echo $XDG_SESSION_TYPE`.
- **Нужен интернет.** Офлайн-режима нет по построению.
- **Аудио уходит в OpenAI**, а при включённом втором этапе транскрипт уходит в
  DeepSeek. Если для того, что ты диктуешь, это неприемлемо — инструмент не
  подходит.
- **Это стоит денег**, хоть и немного: около **$0.0045 за минуту** аудио.
- Проверено на Ubuntu 24.04 с GNOME и PipeWire. Другие конфигурации должны
  работать, но не проверялись.

## Требования

- Linux с X11 и PipeWire
- [`uv`](https://docs.astral.sh/uv/)
- `pw-record`, `pw-play`, `ffmpeg` — обычно уже стоят
- `python3-tk` — для окна правки
- микрофон
- ключ OpenAI (обязателен), ключ DeepSeek (необязателен)

## Быстрый старт

```bash
sudo apt install python3-tk
git clone https://github.com/<ты>/voicetype ~/Projects/develop/voicetype
cd ~/Projects/develop/voicetype
bash install.sh
```

Вписать ключ:

```bash
$EDITOR .env          # OPENAI_API_KEY=sk-...
```

`DEEPSEEK_API_KEY` можно оставить пустым. Тогда этап вычитки просто не
включится — это штатный режим, а не ошибка.

Проверить микрофон и запустить:

```bash
./scripts/check_mic.sh     # запишет 10 с, проиграет, подскажет строку конфига
./bin/voicetype start
```

## Управление

```bash
./bin/voicetype start     # включить
./bin/voicetype stop      # выключить
./bin/voicetype restart   # после правки config.toml или keywords.txt
./bin/voicetype status    # что настроено и работает ли
./bin/voicetype logs      # живой лог
./bin/voicetype history   # последние диктовки (history 20 — последние 20)
./bin/voicetype run       # в переднем плане, для отладки
```

**Если вставка не дошла.** Каждая расшифровка сразу после распознавания пишется
в `.state/history.jsonl` — ещё до окна правки. Туда же попадает итоговый текст
после правки с пометкой «вставлено» или «вставка не удалась».
`voicetype history` показывает последние записи, текст можно скопировать
оттуда. Файл доступен только владельцу (`0600`), в git не попадает, хранится
последних 500 записей.

Удобно добавить в `~/.bashrc`:

```bash
export PATH="$PATH:$HOME/Projects/develop/voicetype/bin"
```

**При загрузке машины не запускается.** systemd-unit ставится, но никогда не
enable-ится: `systemctl --user is-enabled voicetype` отвечает `linked` — «unit
на месте, но его ничто не поднимает». Поднимает только `voicetype start`. Если
автозапуск всё же понадобится — `systemctl --user enable voicetype`.

## Как пользоваться

Клавиша по умолчанию — **правый Ctrl**. Одна клавиша, два режима:

| | |
|---|---|
| **Зажать и говорить** | пишется, пока держишь; отпустил — конец |
| **Коротко нажать** | пишется, пока не нажмёшь второй раз — для длинных мыслей |

Бип на старте, бип на конце, низкий бип при ошибке.

### Окно правки

Появляется всегда. Ничего не попадает в терминал без просмотра.

| Клавиши | Действие |
|---|---|
| `Enter` | вставить в исходное окно |
| `Shift+Enter` | перенос строки |
| `Esc` | отменить |
| `Ctrl+Esc` | отменить и сбросить сессию диктовки |
| `Ctrl+R` | показать текст до вычитки |
| `Ctrl+Z` / `Ctrl+Shift+Z` | отменить / вернуть правку |
| `Ctrl+A` | выделить всё |
| `Ctrl+C` / `Ctrl+V` / `Ctrl+X` | обычная работа с буфером |
| `Ctrl+W` | удалить слово слева |
| правый Ctrl | договорить голосом прямо в это окно |

Пока окно открыто, буфер обмена не трогается — `Ctrl+V` вставит то, что
копировал **ты**. Своё содержимое программа кладёт в буфер только на миг
вставки и сразу возвращает твоё обратно.

### Codex CLI и встроенные терминалы

Поставь курсор в строку Codex CLI, надиктуй текст, проверь его и нажми Enter
в окне правки. VoiceType вставляет текст; для отправки запроса отдельно
нажми Enter уже в терминале.

Если отправить `Ctrl+V` напрямую в Codex, он может запустить вставку картинки
и показать `Failed to paste image: clipboard unavailable` или ошибку таймаута
подключения к X11. Текст должен вставлять сам терминал по `Ctrl+Shift+V`.
Это работает и с Codex на удалённой машине: локальный терминал передаёт текст
в удалённую сессию. Источники: [вставка в терминале VS Code](https://code.visualstudio.com/docs/terminal/basics#_copy-paste),
[работа с изображениями в Codex](https://learn.chatgpt.com/docs/image-inputs?surface=cli).

Автоопределение теперь учитывает VS Code, Code OSS, Code Insiders, VSCodium,
Cursor и Windsurf. В эти окна отправляется `Ctrl+Shift+V`, как в известные
отдельные терминалы. В остальные приложения по-прежнему отправляется `Ctrl+V`.
Существующий `config.toml` получает новые значения для IDE автоматически,
сохраняя твой список `terminal_classes`. После обновления выполни
`./bin/voicetype restart`.

IDE определяется по `WM_CLASS` всего окна: VoiceType не различает редактор
и встроенный терминал. Перед диктовкой в IDE ставь курсор именно в терминал.
Для обычной вставки в редактор задай `terminal_editor_classes = []` в секции
`[inject]`. Классы IDE сравниваются по точному совпадению без учёта регистра;
класс окна покажет `xprop WM_CLASS`.

Для нестандартных привязок клавиш можно явно выбрать сочетание:

```toml
[inject]
method = "clipboard"
paste_shortcut = "ctrl+shift+v" # auto (по умолчанию), ctrl+shift+v или ctrl+v
```

Явное сочетание действует во всех целевых окнах при вставке через буфер.
Убедись, что терминал назначает его на вставку текста. Неизвестный метод или
сочетание даёт ошибку при запуске. Если исходное окно определить не удалось,
вставка останавливается с ошибкой; текст можно взять из `./bin/voicetype history`
и повторить диктовку из нужного окна. В логах есть класс окна и выбранное
сочетание, без содержимого текста.

### Продолжение диктовки

Надиктовал, нажал Enter, текст в терминале. Вспомнил ещё что-то — нажми клавишу
снова: новый кусок встанет следом, старый останется целым. Пробел и заглавная
на стыке подставляются сами.

Сессия привязана к окну и живёт 10 минут (настраивается). Переключился в другое
окно — началась новая. В окне правки предыдущий фрагмент виден сверху серым.

Содержимое терминала программа прочитать не может — этого не может никто, — так
что она помнит только собственные вставки. Если между двумя диктовками
поправить строку руками, стык может ошибиться на один пробел.

## Настройка

Всё в `config.toml`, он создаётся из `config.example.toml` при установке и
игнорируется git. Самое полезное:

```toml
[audio]
source = "auto"          # имя источника PipeWire; check_mic.sh подскажет твоё

[hotkey]
key = "ctrl_r"           # ctrl_r, alt_r, super_r, f13, pause, menu…
hold_threshold_ms = 400  # граница между «зажал» и «тапнул»

[stt]
model = "gpt-transcribe"
languages = ["ru", "en"] # смешанная речь перестаёт транслитерироваться

[cleanup]
enabled = true           # false выключает DeepSeek, даже если ключ есть

[inject]
paste_shortcut = "auto"   # терминал/IDE: Ctrl+Shift+V; остальные окна: Ctrl+V
# terminal_editor_classes = [] # отключить терминальные сочетания для IDE

[ui]
font_family = ""         # пусто = системный шрифт
font_size = 15
```

`keywords.txt` — твой глоссарий, термины, которые модель должна услышать и
написать точно (`kubectl`, а не «кубэ контрол»). Он уходит в модель
распознавания параметром `keywords`, то есть улучшает само распознавание, а не
латает результат постфактум. Дополни под свой стек и сделай `voicetype restart`.

## Как устроено внутри

Несколько решений, которые не видны по коду и стоили реальной отладки:

- **Буфер обмена нельзя отдать из заблокированного цикла событий.** В X11
  владелец буфера обязан ответить на `SelectionRequest`. Владелец — Tk, и если
  между «положили в буфер» и «нажали вставку» заснуть в главном потоке,
  терминал спросит, а ответить будет некому: вставится пустота, притом что все
  логи выглядят успешными. Поэтому шаги вставки разнесены по таймеру Tk.
- **Никогда не вызывать Tk из фонового потока.** `root.after()` из чужого
  потока не падает с ошибкой — он молча теряется. Сетевая работа идёт вне
  главного потока, поэтому результат возвращается через очередь, которую
  разбирает таймер главного потока.
- **`pw-record` игнорирует несуществующий `--target`** и молча пишет с
  устройства по умолчанию. Источник из конфига проверяется на старте — иначе
  опечатка в `config.toml` выглядит как «микрофон почему-то пишет тишину».
- **Bluetooth-гарнитуры тут плохо подходят.** В режиме микрофона они уходят в
  16 кГц HFP с агрессивным шумодавом — ровно неподходящий вход для речи со
  сленгом и акцентом. Дешёвый USB-микрофон обыгрывает дорогие наушники. AirPods
  вдобавок часто вообще не договариваются об HFP на Linux.

Ни одного пакета из `apt`, кроме `python3-tk`: запись — `pw-record`, звуки —
`pw-play`, кодирование — `ffmpeg`, эмуляция клавиш — `python-xlib`.

## Секреты

`.env` лежит в корне проекта и стоит первой строкой в `.gitignore`.
`install.sh` ставит на него `chmod 600` и вешает хук `pre-commit`, который не
даст закоммитить ни сам файл, ни строку вида `sk-...`.

От `git add -f` и от копирования всей папки куда-то ещё это не спасёт.

## Отладка

```bash
./bin/voicetype run -v                                    # лог в терминал
uv run python -m voicetype.stt --file запись.ogg          # только распознавание
uv run python -m voicetype.cleanup --text "ну ээ ребейз"  # только вычитка
```

- **Клавиша не срабатывает** — скорее всего, у тебя Wayland: `echo $XDG_SESSION_TYPE`.
- **Запись пустая** — не тот источник в `config.toml` или гарнитура уснула.
  Прогони `./scripts/check_mic.sh`.
- **Уродливый нечитаемый шрифт** — Tk собран без fontconfig. Поставь
  `python3-tk` и перезапусти `bash install.sh`: он сам выберет подходящий
  интерпретатор.
- **Codex пишет `Failed to paste image`** — проверь сочетание вставки текста.
  Классы IDE задаются в `[inject].terminal_editor_classes`, отдельных терминалов —
  в `[inject].terminal_classes`. Для неопознанного терминала задай
  `paste_shortcut = "ctrl+shift+v"` и перезапусти приложение.
- **Текст вставляется не в то окно** — начинай диктовку с фокусом в нужном окне.
  Проверь цель и выбранное сочетание в `./bin/voicetype logs`.

## Тесты

```bash
uv pip install --python .venv/bin/python -e '.[test]'
.venv/bin/python -m pytest --cov=voicetype.inject --cov-report=term-missing
```

Тесты проверяют выбор сочетания для терминалов, IDE и браузеров, явные настройки,
совместимость со старым конфигом, восстановление буфера, неизвестное целевое окно
и посимвольный режим. Проверки X11 поднимают отдельный дисплей Xvfb и используют
настоящие события XTEST и передачу Unicode через буфер между клиентами Tk.
Тест настоящего `xfce4-terminal` проверяет UTF-8 и многострочный текст внутри
bracketed paste, без дополнительного нажатия Enter.

Для всех интеграционных проверок на Ubuntu установи необязательные инструменты:

```bash
sudo apt install xvfb xfce4-terminal xfwm4 dbus-x11
.venv/bin/python -m pytest
```

Если системных инструментов нет, соответствующие тесты пропускаются. Только
модульные тесты: `.venv/bin/python -m pytest -m 'not x11'`. Тесты не вызывают
API распознавания, не записывают звук и не используют окна рабочего стола.
Полную диктовку внутри Codex нужно проверить вручную со своим терминалом
и привязками клавиш.
